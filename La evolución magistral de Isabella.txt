json

Genera respuesta y, opcionalmente, comandos de automatización.

6. Guía para crear skills personalizadas para Isabella
6.1. Modelo mental
Un skill de Isabella es:

Una función con firma clara: input -> output.

Con scopes explícitos (files.read, calendar.write, tamv.wallet.read).

Con definiciones semánticas (name, description, args) para que el LLM la llame.

6.2. Pasos
Definir el propósito

Ejemplo: tamv.finance.overview

“Generar un resumen diario de movimientos en la wallet del usuario.”

Definir contrato

json
{
  "name": "tamv.finance.overview",
  "description": "Obtiene los últimos movimientos de la wallet TAMV del usuario y genera un resumen estructurado.",
  "parameters": {
    "type": "object",
    "properties": {
      "days": {
        "type": "integer",
        "description": "Número de días hacia atrás para incluir en el reporte"
      }
    },
    "required": ["days"]
  }
}
Implementar runtime

Edge Function (Node/TS o Deno) o servicio local.

Pseudo‑TS:

ts
export async function tamvFinanceOverview(args, ctx) {
  const { days } = args;
  const userId = ctx.userId;

  const txs = await db.query(`
    select * from transactions
    where user_id = $1
      and created_at >= now() - interval '${days} days'
    order by created_at desc
  `, [userId]);

  const summary = computeSummary(txs);

  return {
    transactions: txs,
    summary
  };
}
Registrar skill

Insertar en isabella_skills con runtime="edge-http" y entrypoint HTTP.

Declarar required_scopes=["tamv.wallet.read"].

Vincular a usuario/workspace en isabella_skill_bindings.

Integrar con el LLM

Tu orquestador genera el JSON de herramientas/skills que pasa al modelo (tool calling).

Cuando el modelo pide tamv.finance.overview, el orquestador ejecuta el skill y devuelve la respuesta.

7. Ejemplos de automatizaciones multi‑canal (WhatsApp + Discord)
7.1. Daily Briefing TAMV
Objetivo: cada mañana, Isabella envía un resumen personalizado del día por WhatsApp y un reporte para la comunidad en un canal de Discord.

Proceso:

Scheduler de TAMV (cron/edge function) dispara POST /isabella/v1/automation/daily-briefing.

Isabella:

Usa skill tamv.finance.overview (últimos 3 días).

Usa skill tamv.community.digest (tendencias de grupos/chats).

Usa skill tamv.calendar.daily (eventos de hoy).

Genera dos outputs:

Versión privada → WhatsApp al número del usuario.

Versión agregada → Discord channel #tamv-daily.

Envío:

WhatsApp: API Twilio/Meta, canal configurado en isabella_channels.

Discord: webhook → mensaje embed con secciones.

7.2. Alertas éticas / de riesgo
Si isabella_ethics_events registra un evento critical (ej., auto-daño):

Skill tamv.guardian.alert envía mensaje discreto a un canal seguro de Discord donde solo guardianes ven el evento.

Skill tamv.user.safety envía mensaje de apoyo por WhatsApp con recursos locales (líneas de ayuda), según país.

8.2. Pipeline completo
Input

Procesamiento Isabella

Igual que en web, pero con metadata channel="xr" y modality="voice" en isabella_messages.

Determina contenido, emoción, gestos sugeridos, y pasa por panel ético.
